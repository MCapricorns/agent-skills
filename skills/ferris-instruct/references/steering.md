# Boundaries and Persistence

Strong "ask first" language written for an older model will make a careful one stop where the user already wanted it to continue. Ask only at decisions the user would actually want to make.

A read-only request stays read-only. Commit, push, release, or repo-wide cleanup only when the user asked. Those lines are enough; do not add a review gate after every first draft.

If the request includes getting the change running, inspecting the result, and landing it, that is the job. Say what to explore past a first pass and where to stop. Persistence is not a license to widen scope.
